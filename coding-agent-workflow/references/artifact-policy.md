# 中间产出保留策略

不要把所有中间产出都保存下来。判断标准只有一条：

> 它能否降低未来某人的理解成本、决策成本或重复劳动？

## 三级保留

| 级别 | 内容 | 保留判断 |
| --- | --- | --- |
| **A 必须持久化** | 项目目标、有效需求、重要架构决策、当前任务状态、验收结果、未解决风险 | 丢失它，未来可能做错决策或重复大量工作 |
| **B 有价值时保留** | 方案对比、技术调查、性能实验、复杂 Bug 排查过程、被否决但值得记录的路线 | 能解释不直观的决定，或帮助排障、避免重复试错 |
| **C 默认不保留** | 重复草稿、无信息增量的中间推理、短期调试输出、失效临时文件 | 对未来没有足够价值 |

## 决策记录 vs 过程记录

- **决策记录**（通常长期保存）：结论、背景、考虑过的方案、主要取舍、后果。见 `templates/adr.md`。
- **原始过程记录**（按需保存）：完整终端输出、临时调试日志、实验文件。优先靠 Git 历史、测试结果或外部日志追溯；确需保留时放进任务目录并标注用途。

## 落到哪里

| 产出类型 | 去处 |
| --- | --- |
| 长期结论（需求、架构、决策） | `docs/` |
| 任务过程（简报、分析、计划、验证、交接） | `work/active/<任务>/` |
| 可复用的自动化 | `scripts/` 或项目正式脚本目录 |
| 正式测试 | `tests/` |
| 临时草稿 | 临时目录，并设清理策略 |

## 反模式

- 强迫每个任务产出全套文档 → 制造噪音，Agent 为填模板而编造内容。
- 把分析结论只留在聊天里 → 换对话即丢失。
- 同一份信息在多处维护 → 半年后出现多个版本。
- 长期保存原始日志 → 淹没真正有价值的记录。
